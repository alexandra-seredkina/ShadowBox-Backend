# **ShadowBox**

## Анонимная и безопасная электронная почта

Проект **ShadowBox** — почтовый сервис, который не знает, кто вы, и не может прочитать ваши письма. Без телефона, без привязки к другой почте, без анализа содержимого.

Репозитории:

- [ShadowBox-Backend](https://github.com/alexandra-seredkina/ShadowBox-Backend) — API, база данных, инфраструктура (вы здесь)
- [ShadowBox-Frontend](https://github.com/alexandra-seredkina/ShadowBox-Frontend) — веб-интерфейс

## Почему это важно

Сколько аккаунтов привязано к вашей почте? При регистрации почти везде указывают почту, и через неё же восстанавливают пароль. Ключ к почте — ключ ко всей цифровой жизни: скомпрометировав один ящик, злоумышленник получает доступ почти ко всем сервисам, документам и перепискам.

И кому мы эту почту доверяем? [Яндекс признал](https://yandex.ru/company/news/2021-02-12), что сотрудник получил несанкционированный доступ к 4887 почтовым ящикам. [Google подтвердил](https://www.bbc.com/news/technology-44699263), что письма пользователей могут читать сторонние разработчики приложений, и это не противоречит его политике.

## Принципы

### 1. Сервер не может прочитать ваши письма

Шифрование «AES на сервере» не защищает от администратора, если ключ лежит рядом с данными. Поэтому ShadowBox использует схему *zero-access*:

- у каждого пользователя есть пара ключей; приватный ключ хранится только зашифрованным паролем пользователя и расшифровывается в браузере;
- входящее письмо шифруется публичным ключом получателя сразу после приёма, до записи на диск;
- исходная открытая версия письма на сервере не сохраняется.

### 2. Сквозное шифрование там, где оно возможно

E2E работает между пользователями ShadowBox и с внешними адресатами, у которых есть PGP-ключ. Письмо от обычного Gmail или Яндекса приходит по SMTP в открытом виде, его видел отправитель и его провайдер. Мы шифруем такие письма при получении, но не можем сделать вид, что их не существовало до нас.

### 3. Минимум данных

- **Без телефона и чужой почты.** Для регистрации нужны только логин и пароль.
- **IP-адреса не хранятся и не логируются.** nginx не пишет IP в лог и не передаёт их бэкенду. Привязка сессии к IP ломает вход через Tor и VPN и создаёт журнал, который можно изъять, поэтому от неё отказались.
- **Защита сессий без IP:** cookie `HttpOnly` + `Secure` + `SameSite=Strict`, строгий CSP против XSS, короткоживущие сессии, список активных устройств с возможностью завершить любое.

### 4. Защита от злоупотреблений без слежки

Регистрация без телефона привлекает спамеров, а один спамер может отправить в блэклисты весь домен, и письма честных пользователей перестанут доходить. Вместо идентификации:

- proof-of-work при регистрации, которое дорого для ботов и незаметно для человека;
- лимиты на отправку для новых аккаунтов;
- rate limiting на nginx, без сохранения IP.

### 5. Много адресов вместо одного

Временные адреса и алиасы для каждого сервиса: утечка одного адреса не выдаёт остальные, спам легко отрезать, а OSINT-разведке труднее связать аккаунты между собой. Письма с незнакомых адресов и подозрительные письма помечаются в интерфейсе.

### 6. Открытый код и проверяемая безопасность

Код открыт под [AGPL-3.0](LICENSE): любой может проверить, что сервис делает то, что обещает.

## Модель угроз

Описывает целевую архитектуру; что из этого уже реализовано, видно в разделе «Статус».

| Угроза | Защита |
| --- | --- |
| Утечка базы данных или дампа диска | ✅ письма зашифрованы ключами пользователей |
| Любопытный администратор | ✅ не может расшифровать сохранённые письма |
| Кража сессии через XSS | ✅ HttpOnly cookie и CSP с nonce |
| Деанонимизация по данным регистрации | ✅ данные не запрашиваются, IP не хранятся |
| Метаданные: кто, кому и когда пишет | ⚠️ частично: они нужны SMTP для доставки |
| Внешний отправитель и его провайдер | ❌ видят письмо до того, как оно дойдёт до нас |
| Взломанное устройство пользователя | ❌ вне зоны ответственности сервиса |
| Сервер, подменивший JavaScript веб-клиента | ⚠️ частично: код открыт, но веб-клиент получает JS с сервера; в будущем — нативный клиент |

## Разработка

Нужны Docker с Compose и оба репозитория, склонированные рядом:

```
ShadowBox/
├── ShadowBox-Backend/
└── ShadowBox-Frontend/
```

Запуск:

```bash
cp .env.example .env   # задайте свой POSTGRES_PASSWORD
docker compose up --build
```

| Адрес | Что |
| --- | --- |
| http://127.0.0.1:8080 | веб-интерфейс через nginx |
| http://127.0.0.1:8080/api/health | состояние API и базы |
| 127.0.0.1:5433 | Postgres (для Prisma Studio и миграций с хоста) |

Код фронтенда и бэкенда монтируется в контейнеры и перезагружается при изменениях. После изменения зависимостей пересоберите контейнеры с новыми volume:

```bash
docker compose up --build -V
```

Новая миграция после изменения `prisma/schema.prisma`:

```bash
npx prisma migrate dev --name <название>
```
